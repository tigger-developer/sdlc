This is the canonical SDLC v3 specification template.

Use a new project-wide work number and never reuse an identifier. Replace every
instructional placeholder before definition sign-off. Keep the document concise,
but make it sufficient for a new agent to deliver without the drafting
conversation. Use Org emphasis sparingly: bold functional nouns, states, values,
and consequences that support rapid scanning. Do not bold structural words.

Lifecycle states are =DRAFT=, =AWAITING_SIGNOFF=, and =APPROVED=. Only an
effective definition-gate PASS may set =DEFINITION_GATE= to =PASS=. Only
explicit operator sign-off may set =SDLC_STATE= to =APPROVED= and replace
=OPERATOR_SIGNOFF= with the authority and date. Any later material specification
change resets all three fields to their initial values. Detailed audit evidence
remains in =audits.org=.
#+end_comment

* Test Definitions
:PROPERTIES:
:CUSTOM_ID: test-definitions
:END:

#+begin_comment
Use the test classifications and automated TDD rule resurrected from SDLC v1.
Classify each test honestly:

- RT is a persistent automated regression test included in the normal suite.
- UT is a human user test whose result is recorded, with no artificial test file.
- OT is a bounded one-off check that is not retained in the regression suite.

Automated RTs follow TDD and must fail for the expected reason before
implementation. A test must earn its place, exercise the relevant boundary, and
be defined well enough to reproduce. Do not simulate an undocumented third-party
system or use source-text greps as behavioural evidence.
#+end_comment
