** Outcome
- The initializer invokes the configured *writing agent* for each migration task.
** Before
- *Ticket migration* and *AC conversion* both selected the audit settings and
  rejected every harness except *Codex*.
- *AC repair* also selected the audit settings; a failed launch could leave
  *resume* skipping ticket migration.
** After
- *Ticket migration* uses =delivery.audit= as a model-selection profile, not an
  audit role. *AC conversion and repair* use =delivery.definition=.
- *Codex, Hermes and Claude* run directly with editing tools available and
  their native command policies retained. *Copilot* retains a manual handoff.
- A *canonical ledger* still merges deterministically, without an agent.
** Changes
- Separate configuration selection from invocation role; keep prompts literal,
  project-local execution, and repair revalidation.
** Unchanged
- No *audit harness*, config schema, global configuration, client project,
  deployment or ticket-classification rules change.
** Edge cases
- A *failed agent* stops migration; *invalid repair* never enters the work ledger.
- *Missing Hermes provider* fails before launch; unsupported adapters give a
  handoff. Resume offers ticket migration if its existing index is absent.
** Decisions
- Use the audit profile for *bulk processing*, the definition profile for
  *requirements preservation*, and no agent for a *valid Org merge*.
** Next step
- Review the emergency change, release it, then operator installation and migration.

* Edge Cases
- Existing =docs/ticket-migration.org= retains its prior skip behaviour. This

- Unsupported adapters retain manual handoff; no automatic provider fallback or
  permission-bypass switches are added.

* Solution Design
** Architecture context
- Keep the initializer's =RunCommand= seam for direct native invocations.
  Do not use =sdlc-harness=, audit records, audit sessions or audit timeouts.
** Invocation contract
- Callers select =SDLC_AUDIT= for ticket migration, =SDLC_SPEC= for conversion
  and repair. These are resolved schema keys, not new configuration.
- Codex :: =exec --ephemeral --sandbox workspace-write --model MODEL -=.
- Hermes :: =chat --query-file - --oneshot --in PROJECT --model MODEL --provider PROVIDER=.
- Claude :: =--print --permission-mode acceptEdits --model MODEL=, prompt on stdin.
- Omitted model :: Preserve the native harness default; production values are
  resolved by the existing configuration schema.
- Failure :: Return native errors; retain initialization state and source files.
  Repair is invoked at most once per attempt and revalidated before merge.
** Security impact
- The operator authorizes *project migration writes*, not a read-only audit.
  No shell interpolates the prompt, no tools are disabled, and no global config,
  authentication store, hook or dangerous-command approval policy is changed.
- Hermes and Claude retain native policies and skill-defined project scope;
  this change does not claim a new filesystem sandbox for them.
