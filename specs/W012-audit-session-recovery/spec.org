* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:
** Outcome
- *Unavailable sessions* and *authentication failures* no longer require manual audit-record repair.
- *Identical audit requests* reuse their recorded verdict without another model call.
** Before
- A changed *audit harness* rejects the retained session.
- An explicit *missing session* or *logged-out provider* blocks further auditing.
** After
- The harness creates a *replacement context* for configuration changes or a recognized missing session.
- An optional *authentication fallback* selects the operator-configured alternate tuple.
** Changes
- Record *session ownership*, replacement reason and per-round provenance in =audits.yaml=.
- Give replacements *all current evidence* and *historical findings*.
- Cache *PASS*, *FAIL* and *PROVISIONAL PASS* by the whole request's *SHA-256* identity.
- Give tools-disabled *Hermes* verified evidence through stdin without retained document copies.
** Unchanged
- Preserve *findings*, *round budget*, *per-attempt timeout* and *human approval* boundaries.
- No fallback for *FAIL*, *timeouts*, *permission denials* or *unclassified failures*.
** Edge cases
- Stop at *max_rounds* even if replacement would otherwise apply.
- Older records with unknown model/provider retain that historical uncertainty.
** Decisions
- *OT only*: the operator explicitly excluded new regression tests and accepted bounded API cost.
- *Project fallback* replaces the entire global tuple; an empty mapping disables it.
** Next step
- Release the verified source for *operator-run installation*, then confirm deployed behaviour before closure.

:PROPERTIES:
:CUSTOM_ID: ac012-2

** AC012.3 - Preserve bounded failure semantics
:PROPERTIES:
:CUSTOM_ID: ac012-3
:END:
- Criterion :: Replacement never resets audit rounds or creates a verdict. A command permits at most one missing-session restart and one authentication fallback. Unclassified failures, permission errors, timeouts and FAIL verdicts do not trigger fallback.
- Proven by :: [[#ot012-1][OT012.1 - Local recovery cases]].
** AC012.4 - Deploy the verified helper
:PROPERTIES:
:CUSTOM_ID: ac012-4
:END:
- Criterion :: The operator-run installation deploys the revised helper, prompts and instructions; the installed helper can resolve the configured fallback.

** AC012.5 - Reuse identical completed audits
:PROPERTIES:
:CUSTOM_ID: ac012-5
:END:
- Criterion :: An unchanged request returns its recorded PASS, FAIL or PROVISIONAL PASS and findings without another provider invocation, record mutation or round. Identity includes work item, gate, all supplied paths and content hashes, audit instructions/context and primary/fallback model configuration. Incidents and unkeyed historical records are not cache results.

* Edge Cases
- Unknown native error formats remain *incidents*, not proof of a missing session.
- Empty native identity after an interrupted start still requires operator recovery; no session is guessed.
- Exhaustion prevents additional provider launches, including replacement.

* Solution Design
** Architecture context
- Extend the existing fixed-adapter runner and harness-owned YAML record; no new service or dependency.
** Configuration
- After-state :: =delivery.<definition|build|audit>.fallback= contains =harness=, =provider= where required and =model=.
- Inheritance :: Global mapping unless replaced by a project mapping; =fallback: {}= disables. No fallback CLI/environment overrides.
- Provider :: Required for Hermes, ignored for Codex/Claude/Copilot.
** Recovery
- Known configuration change selects a new primary session; a previously selected fallback remains active while both tuples still match.
- Provider error classification reads bounded error diagnostics, not assistant review prose. Claude's exact missing-conversation message must name the requested ID.
- Persist retired identity/tuple/reason and per-attempt identity/tuple. New contexts receive full current manifest and history; resumes retain manifest comparisons.
- Each attempt keeps the configured deadline and consumes the same recorded budget.
- Hermes :: Use native =chat --quiet --query-file -= rather than top-level =-z=, which bypasses resume/session options in the installed CLI. Read native =session_id:= from stderr; never ask the model to invent or repeat an ID.
- Hermes evidence :: Keep tools disabled; send verified UTF-8 source contents as JSON data over stdin on each invocation. No on-disk evidence copies or contents in =audits.yaml=. Codex/Claude retain path-based transport.
** Result cache
- Store =history[].cache_key= alongside each attempt. Hash canonical request data with SHA-256: work/gate, sorted evidence manifest, prompt registry, supplied context and primary/fallback tuples.
- Look up the newest matching validated, incident-free response before provider/session admission and round-limit checks. Return the exact response with a cache diagnostic; do not change the record.
- Never cache an incomplete attempt or fabricate keys for historical responses. Supplied file changes invalidate the cache; unlisted ambient reads are not covered. Execution limits alone do not change the verdict identity.
** Security impact
- No access grant changes, credentials copied or login attempts. Fallback grants only the already-authorized invocation to the explicitly configured provider.
- Do not interpret permission failures or arbitrary provider errors as authentication failures. No secrets are added to records.
