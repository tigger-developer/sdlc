* Read supplied external evidence in Claude audits

- Outcome :: Claude audits can *read explicitly supplied external evidence*.
- Before :: The manifest names external files but the adapter grants no corresponding permission.
- After :: Each start and resume supplies *exact Read rules* for the manifest files.
- Changes :: Invocation-local Claude settings and evidence plumbing.
- Unchanged :: Read-only built-in tool selection, plan mode, authentication,
  existing deny rules, other providers, timeout, round limits and retained sessions.
- Edge cases :: Symlinked parent directories, literal glob characters, spaces,
  prohibited or unsupported paths, and provider policies that still deny access.
- Decisions :: Operator invoked =BYPASS-GATE-7= for this bounded permission fix.
- Next step :: Verify the fix and present it for operator closure; no client-project edits.

-----

* Context

The reported audit named five external files as unreadable despite their presence
in =--input=. The CLI captures those inputs, but the Claude adapter previously
passed only the manifest text. The operator authorized translating that supplied
evidence into read permissions, not opening whole directories or enabling writes.

Authority: [[file:../../docs/ARCHITECTURE.md][SDLC architecture]], the operator's
emergency request, and [[https://code.claude.com/docs/en/permissions#read-and-edit][Claude Read permission syntax]].
[[file:../W010-harness-filesystem-boundaries/spec.org][W010 - Harness filesystem boundaries]]
remains the separate, broader enforcement work; this change does not implement it.

* Acceptance Criteria

** AC011.1 - Supplied files receive exact read grants
:PROPERTIES:
:CUSTOM_ID: ac-011-1
:END:
- Claude *start and resume* grant Read permission for each supplied file and
  its resolved alias target, including files outside the project.
- Literal pattern characters in filenames must *not expand the grant*.
- Proved by :: [[#rt-011-1][RT011.1 - Exact adapter grants]], [[#rt-011-2][RT011.2 - CLI resume integration]], [[#ot-011-1][OT011.1 - Native external read]].

** AC011.2 - Existing restrictions and recovery remain intact
:PROPERTIES:
:CUSTOM_ID: ac-011-2
:END:
- Grants add *no directory or write permissions*, and do not disable existing
  hooks or deny rules. Native policy may still refuse a file; no bypass is permitted.
- The CLI retains the recorded work-item/gate session on resume.
- Invalid permission paths are rejected before provider invocation.
- Proved by :: [[#rt-011-1][RT011.1 - Exact adapter grants]], [[#rt-011-2][RT011.2 - CLI resume integration]].

* Edge Cases

- Parent path aliases need grants for both original and resolved paths.
- Glob characters and trailing spaces are escaped, not treated as wildcards.
- Parentheses remain literal: [[https://code.claude.com/docs/en/permissions#permission-rule-syntax][Claude permission rule syntax]]
  explicitly permits parentheses inside a specifier without escaping them.
- This emergency adapter supports absolute POSIX permission paths; non-POSIX
  paths, control characters and unresolved files fail explicitly.
- Existing policy may deny supplied evidence despite a Read grant. Report that
  limitation; do not widen permissions or invent a completed read.

* Solution Design

- Architecture :: Pass the captured =Evidence.Files= through =harness.Request=.
  The Claude adapter projects the list through one shared helper on start/resume.
- Interface :: JSON-encoded =--settings= containing =permissions.allow= with
  exact =Read(//absolute/path)= rules before the positional prompt argument;
  no persistent configuration file is edited.
- Native contract :: [[https://code.claude.com/docs/en/settings#settings-precedence][Claude settings precedence]]
  documents command-line JSON merging, retention of omitted lower-level keys,
  and list merging. Only =permissions.allow= is supplied; deny and hook settings
  are not replaced or disabled. Managed restrictions retain precedence.
- Security :: Resolve aliases, escape gitignore metacharacters, reject unsupported
  paths, preserve =--tools Read --permission-mode plan= and existing deny policy.
  This adds permissions for supplied evidence, not a complete filesystem sandbox
  or revocation of permissions already present in native configuration/session state.
- Other providers and existing evidence hash verification are unchanged.
