* Support Claude, Copilot, and Hermes Harnesses
:PROPERTIES:
:CUSTOM_ID: summary
:END:

- Outcome :: The *lean SDLC v3 workflow* is *natively usable* from *Codex*,
  *Claude Code*, *GitHub Copilot CLI*, and *Hermes* without duplicating its
  canonical standards or skills.
- Before :: SDLC v3 *installs and runs through Codex only*; installation
  deliberately retires SDLC workflow artefacts from the other three harnesses.
- After :: Each supported harness can *discover the global SDLC skills*, run
  the *same definition and delivery workflows*, and start or resume the *single
  external audit context* through an explicit capability adapter. Its native
  pre-tool hook also enforces the *canonical SDLC command and path
  restrictions*.
- Changes :: Add *Claude*, *Copilot*, and *Hermes* harness adapters; expose the
  *canonical global skills* through each native skill location; make harness
  selection and headless execution *capability-aware*; register the *shared
  command guard* through each harness's native hook mechanism; correct its
  *command-position parsing*; replace hard-coded *Codex* language in the
  workflow and initializer.
- Unchanged :: The *standards*, *two-gate workflow*, *five-round limit*,
  *operator sign-off*, *Codex support*, and rule against *project-local skill
  copies* remain unchanged.
- Edge cases :: Handle an *absent executable or provider home*, *unsupported or
  meaningless provider option*, *non-SDLC destination conflict*, *unprovable
  read-only mode*, *guarded words used only as data*, *option-bearing wrappers*,
  *unavailable or incompatible pre-tool hooks*, *timeout*, *missing session
  identity*, and *malformed final response* without claiming parity or PASS.
- Decisions :: Keep one *provider-neutral source of truth* under =~/.agents=;
  use *fixed Go adapters*, not shell command templates; treat actual harness
  smoke checks as *bounded one-off tests*, never regression tests.
- Next step :: *Definition gate*, then *operator sign-off*.

The summary above accurately and completely represents the detailed
specification below.

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem

SDLC v3 was deliberately restored with *one supported harness* so the lean
workflow could be stabilized. The current installer *removes workflow skills*
and *SDLC command hooks* from Claude, Copilot, and Hermes, the project schema
*accepts only Codex*, and the audit contract *hard-codes Codex*. The same
established workflow and command-policy enforcement therefore cannot be used
through the other installed coding agents.

** Outcome

The four harnesses provide the same *SDLC semantics* while their adapters honour
their different native skill paths, command-line arguments, model controls,
provider controls, output formats, and resumable-session mechanisms.

Support means *interactive global-skill invocation* and *bounded headless
operation* where the workflow requires it. It does *not promise identical
provider, permission, or output features*.

** Scope

*** In scope

- *Native global-skill exposure* for Claude Code, GitHub Copilot CLI, and
  Hermes, while retaining Codex.
- *Native pre-tool hook registration* of the canonical SDLC command guard for
  all four supported harnesses.
- *Harness selection* in global and project YAML configuration.
- *Fixed adapters* for bounded headless start and resume operations.
- *Provider-neutral routing* in the initializer and composite audit workflow.
- *Capability checks*, *least-privilege audits*, *safe installation*, accurate
  help, and public documentation.

*** Out of scope

- *No installation* of a harness, model, credential, subscription, or provider.
- *No guarantee* that every harness offers every model.
- *No project-local copies* of SDLC skills.
- *No Spec Kit restoration*.
- *No fifth harness* or user-authored command template.
- *No replacement* of private provider configuration with public defaults.

*** Unchanged

- =~/.agents/sdlc= remains the *canonical standards root*.
- =~/.agents/skills= remains the *canonical global skill source*.
- The authoring context still performs *local audits first*, followed by at
  most *one retained external audit context*.
- A timeout, silence, malformed result, or unavailable harness remains a
  *runner incident* and *never becomes PASS*.

** Authority and starting point

- Project profile :: [[file:../../.sdlc/project.yaml][=.sdlc/project.yaml=]]
- Product authority :: [[file:../../README.md][=README.md=]] and
  [[file:../../QUICKSTART.md][=QUICKSTART.md=]] define *installation and operator
  use*.
- Architecture authority :: [[file:../../docs/ARCHITECTURE.md][=docs/ARCHITECTURE.md=]]
  defines the *runtime tree, provider boundary, and two-context gates*.
- Historical evidence :: Tag =v2.0.0= shows prior *multi-provider copied skills*,
  not one canonical global source. Commit =b534241= demonstrates the canonical
  *command guard integrated with all four harnesses* before the v3 emergency
  rollback.
- Current implementation fact ::
  [[file:../../internal/installer/installer.go][=internal/installer/installer.go=]]
  currently *retires non-Codex SDLC skills and command hooks*, and
  [[file:../../src/config/project-init.schema.yaml][=src/config/project-init.schema.yaml=]]
  permits *only Codex and OpenAI*. The current guard also contains parser defects
  that over-block words used as data and miss option-bearing command wrappers;
  those defects are implementation inputs, not intended policy.
- Observed harness interfaces :: The current command contracts are recorded in
  the [[#harness-capability-contract][harness capability contract]]. They must be
  *revalidated during implementation*, not treated as vendor guarantees.
- External contract :: None.

** Constraints and dependencies

- Provider adapters remain *thin*; workflow rules and skill bodies *do not fork*.
- Commands use *compiled allowlisted adapters*; configuration *never supplies
  executable or shell templates*.
- Regression tests use *temporary homes and fake harnesses* with *no metered
  model or real provider mutation*.
- Installation *preserves unrelated provider material* and never assumes a
  same-named artefact is SDLC-owned.
- Hook integration uses each harness's *native pre-tool mechanism* and the one
  canonical =~/.agents/sdlc/hooks/agent-command-guard.sh= implementation.

** Decisions

- Native skill locations expose a *managed link* to canonical
  =~/.agents/skills/<skill>=, never a copied body.
- One *shared Go harness registry* supplies capabilities; each adapter builds a
  *fixed argument vector*.
- Pass =provider= *only when independently supported*; ignore irrelevant
  inherited values and *reject conflicting explicit overrides*.
- External audit obtains one *stable session identity* and *resumes that exact
  context*; otherwise the gate stops.
- An installed harness is *not SDLC-ready* unless its native pre-tool hook can
  invoke and enforce the canonical command guard without weakening unrelated
  provider configuration.
- Command detection is *syntax-aware*: it blocks a prohibited executable only
  in command position, follows supported wrappers to their invoked executable,
  and does not treat ordinary argument text as a command.

** Unresolved blockers

- None.

* Edge Cases
:PROPERTIES:
:CUSTOM_ID: edge-cases
:END:

** Provider home is absent

- Condition :: An *installed harness executable* has *no native skill home*.
- Required behaviour :: Automatic detection uses the *installed executable*.
  When it exists, installation creates the documented native skill directory
  and managed links. Codex, Claude, and Copilot may gain only their documented
  *minimal managed hook artefact* after it appears in the installation plan;
  Hermes requires its provider-owned first-run configuration and *stops rather
  than inventing authentication or model state*. A configured harness whose
  executable is absent stops with the exact prerequisite.
- Covered by :: [[#ac-004-6][AC004.6 - Safe and idempotent installation]] and
  [[#rt-004-1][RT004.1 - Install native global skill adapters]], and
  [[#rt-004-7][RT004.7 - Enforce the command guard across harnesses]].

** Native skill name conflicts

- Condition :: A provider home contains an *unrecognized same-named skill path*.
- Required behaviour :: The installer *reports the exact conflict* and requires
  *operator disposition*; it does *not overwrite, merge, or retire* the path.
- Covered by :: [[#ac-004-6][AC004.6 - Safe and idempotent installation]] and
  [[#rt-004-1][RT004.1 - Install native global skill adapters]].

** Native command-hook integration is unavailable

- Condition :: A harness has *no compatible pre-tool hook*, its provider-owned
  configuration is unavailable, or an *unknown same-path artefact* prevents
  safe registration.
- Required behaviour :: Preserve the existing provider state, report the exact
  capability or path conflict, and mark that harness *not SDLC-ready*. Do not
  silently omit the guard or claim equivalent support.
- Covered by :: [[#ac-004-11][AC004.11 - Consistent command-policy
  enforcement]] and [[#rt-004-7][RT004.7 - Enforce the command guard across
  harnesses]].

** Prohibited words occur only as data

- Condition :: An allowed command receives =source=, =git remote add=,
  =chmod 777=, =python3=, or another guarded token sequence as *ordinary
  argument data*.
- Required behaviour :: The guard returns *no block* because no prohibited
  executable, option, or path is in its guarded syntactic position.
- Covered by :: [[#ac-004-11][AC004.11 - Consistent command-policy
  enforcement]] and [[#rt-004-7][RT004.7 - Enforce the command guard across
  harnesses]].

** Prohibited command follows an option-bearing wrapper

- Condition :: A prohibited executable follows assignments or a supported
  wrapper with options and option values, such as =sudo -u builder rm
  obsolete.txt=.
- Required behaviour :: The guard reaches the *invoked executable* and blocks
  it. An unknown wrapper option fails closed with an actionable diagnostic; it
  does not silently skip an uncertain token.
- Covered by :: [[#ac-004-11][AC004.11 - Consistent command-policy
  enforcement]] and [[#rt-004-7][RT004.7 - Enforce the command guard across
  harnesses]].

** Harness cannot prove read-only execution

- Condition :: A harness *cannot prevent external-auditor mutation*.
- Required behaviour :: External audit *stops as unsupported*; definition or
  delivery does *not weaken the boundary or switch harnesses*.
- Covered by :: [[#ac-004-5][AC004.5 - Read-only audit boundary]] and
  [[#rt-004-4][RT004.4 - Reject invalid audit runner outcomes]].

** Provider is meaningless to the selected harness

- Condition :: Configuration inherits a *meaningless provider value* for Claude,
  Copilot, or Codex.
- Required behaviour :: The adapter *does not pass the provider*. An inherited
  value is ignored with evidence; an *explicit conflicting override is
  rejected*.
- Covered by :: [[#ac-004-3][AC004.3 - Capability-aware phase configuration]]
  and [[#rt-004-2][RT004.2 - Resolve harness configuration]].

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Relevant components :: *Installer*, *initializer*, *YAML schema*, *global
  skills*, *canonical command guard*, *composite audits*, and a new *internal
  harness runner*.
- Ownership boundary :: This repository owns *SDLC adapters and invocation
  semantics*; each harness owns *authentication, models, sessions, and CLI
  compatibility*.
- Existing pattern :: Retain *plan/apply/verify* and the *schema-driven
  initializer*; replace the non-Codex retirement branch.

** High-level design

*** Flow

1. A *compiled registry* declares four supported harnesses and their stable
   configuration and routing capabilities.
2. =sdlc-install= exposes *canonical skills* through each native global skill
   path while preserving provider-owned material.
3. =sdlc-install= registers the *canonical command guard* through each
   harness's native pre-tool hook while preserving unrelated configuration.
4. Interactive harnesses invoke the *same skill bodies*, selected standards,
   and project authorities.
5. A bounded headless operation uses one *fixed adapter* with exact scope,
   model, applicable provider, timeout, and output contract.
6. An external composite audit records one *stable session identity* and uses
   the *same adapter and identity* for every permitted resume.

The runner is used only after all required *same-context local audits pass*.
It *never replaces local review* and *never starts one external context per
focused audit*.

*** Interfaces and configuration

**** Command guard contract
:PROPERTIES:
:CUSTOM_ID: command-guard-contract
:END:

- Canonical implementation ::
  =~/.agents/sdlc/hooks/agent-command-guard.sh= remains the *only policy
  implementation*. Provider integrations adapt native hook payloads to it; they
  do not fork its decisions.
- Guarded paths :: Block reads of any file whose *exact basename is =.env=*,
  whether supplied to a shell command or a recognized native file-reading tool.
  Do not broaden this into a ban on similarly named files.
- Guarded commands :: Block direct =python=, =python3=, =rm=, =sed=, and =awk=
  invocations, including command chains, =env=/=command=/=sudo= prefixes, and
  =bash=/=sh=/=zsh= command-string wrappers.
- Guarded bypasses and access changes :: Block =--no-verify=, =--no-hooks=,
  =--no-pre-commit-hook=, =chmod 777=, =git remote add=, force-push forms,
  =gh repo create=, =gh repo edit=, and arbitrary =source= or =.= file
  execution when they occupy the relevant command or option position, not when
  an allowed command prints or otherwise carries those words as data. These
  remain operator actions where the governing rules permit them; an agent does
  not bypass the hook.
- Allowed neighbours :: The canonical guard returns *no block* for commands and
  paths outside that exact policy; provider-native restrictions still apply.
  The adapter does not add undocumented restrictions or turn a missing or
  unrecognized payload into silent policy success.
- Command-position grammar :: Parse each simple command from its start or from
  a shell control separator; skip leading assignments; follow =env=, =command=,
  =sudo=, control-flow, and timing wrappers using an explicit option-arity
  table; recursively parse only the command-string argument of
  =bash=/=sh=/=zsh= with =-c=. Once an allowed executable is identified, its
  remaining arguments are data except for the separate exact =.env= path and
  guarded option checks. =command -v= and =command -V= inspect names rather than
  invoke them and therefore receive no block.
- Required command vectors :: Block direct and absolute prohibited executables,
  leading assignments, pipelines, compound commands, nested shell command
  strings, =env MODE=test rm obsolete.txt=, =command rm obsolete.txt=, and
  =sudo -u builder rm obsolete.txt=. Return no block for =printf '%s\\n'
  python3=, =echo source file=, =echo git remote add example=, =echo chmod 777
  target=, =echo --no-verify=, =echo git push --force=, =echo gh repo create=,
  =rg python3 README.md=, =command -v python3=, =pythonista --version=, and
  =python3.14 --version=.
- Required path vectors :: Block native reads and shell references to =.env=,
  =config/.env=, =./.env=, and the equivalent backslash path. Return no block
  for =.env.example=, =.env.local=, a search pattern containing =.env= against
  another file, or a native write whose destination is =.env=.
- Native registration :: Codex uses =~/.codex/hooks.json=, Claude uses
  =~/.claude/settings.json=, Copilot uses
  =~/.copilot/hooks/sdlc-tool-guard.json=, and Hermes uses
  =~/.hermes/config.yaml=.
- Payload and result contract ::

  | Harness | Accepted native input projected to the guard | Block result | Allowed result |
  |---------+----------------------------------------------+--------------+----------------|
  | Codex | =hook_event_name=, =tool_name=, =tool_input.command= or named file fields | exit 2 and reason on stderr | exit 0, no block response |
  | Claude | =hook_event_name=PreToolUse=, =tool_name=, =tool_input.command= or named file fields | exit 2 and reason on stderr | exit 0, no block response |
  | Copilot | =hookEventName=, =toolName=, =toolArgs.command= or named file fields | exit 2 and reason on stderr | exit 0, no block response |
  | Hermes | =hook_event_name=pre_tool_call=, =tool_name=, =tool_input.command= or named file fields | exit 0 with JSON =decision:block= and reason | exit 0 with no response |

  Implementation revalidates these native field and result contracts against
  the installed harness versions. Invalid JSON, a recognized command or read
  event missing its required command/path fields, or a changed native schema
  produces a *non-success diagnostic*; it is never treated as an allowed event.
- Absent configuration :: The Codex, Claude, and Copilot adapters may create
  only their *minimal managed hook artefact*. Hermes requires its existing
  first-run configuration and fails with an actionable prerequisite rather than
  synthesizing provider-owned state.
- Ownership :: Embedded Codex, Claude, and Hermes entries are SDLC-owned only
  when their parsed command vector is exactly =bash= plus the current user's
  =~/.agents/sdlc/hooks/agent-command-guard.sh=, or =bash= plus that provider's
  legacy =~/.<provider>/sdlc/hooks/agent-command-guard.sh=. Quoting differences
  do not change that vector; prefixes, suffixes, or additional arguments make it
  unrelated. Other entries remain untouched. The dedicated Copilot file is
  SDLC-owned only when it parses as =version: 1= with a
  =hooks.preToolUse= list containing exactly one command hook whose parsed vector
  has that canonical or Copilot-legacy identity and only the documented =type=,
  =command=, and =timeoutSec= fields. A malformed file or one outside that shape
  is an *unknown same-path conflict*.
- Conflict disposition :: For each unknown conflict, show its exact path and
  intended managed replacement and ask once whether to replace it. Acceptance
  creates an adjacent timestamped byte-for-byte backup before replacement.
  Decline leaves it untouched and makes that harness not ready; independent
  provider changes may proceed only through the final installation confirmation.
- Observable readiness :: After verification, print one line per detected
  harness in the form =Harness <name>: interactive=READY|NOT_READY;
  external-audit=READY|UNAVAILABLE|NOT_READY;
  initializer=READY|HANDOFF|NOT_READY=, followed by a path and reason for every
  non-ready capability. A missing or unverified guard makes =interactive= and
  all agent-execution capabilities =NOT_READY= and gives the installer a
  non-zero final status. =UNAVAILABLE= is reserved for an optional capability
  the native harness cannot provide and is not a successful substitute.
- Verification :: Installation validates that an equivalent native pre-tool
  event reaches the canonical guard and receives its decision. Registration
  without a proven invocation path does *not* make the harness SDLC-ready.

The table is the *current implementation target*. =PROMPT= is *data, never shell
code*. =BUNDLE= is an *isolated audit directory*. Implementation rechecks each

For Claude, Copilot, and Hermes, the *empty tool selection must be proven* to
expose *no tools*. If a current version cannot do that, its adapter may still
provide *interactive skills* but must report *external audit as unavailable*.
Codex runs against the audit bundle with its documented *read-only sandbox*.

- Response envelope :: Require a *non-empty final response* and *one stable
  identity*. Hermes additionally returns
  =SESSION_ID: <native-id>= before the composite gate verdict. Missing,
  duplicated, or malformed fields are runner incidents.
- Incident kinds :: Return one *typed incident*: =executable-unavailable=,
  =capability-unsupported=,
  =configuration-invalid=, =start-failed=, =identity-missing=,
  =response-empty=, =response-malformed=, =timeout=, =resume-failed=, and
  =audit-input-mutated=.
- Process control :: Use a *Go argument slice*, stream *progress to stderr*,
  capture *structured protocol output*, and on timeout *terminate the process
  group*; partial output is diagnostic evidence, never a verdict.

- Harness registry :: A *Go interface with fixed registrations* for =codex=,
  =claude=, =copilot=, and =hermes=. Capabilities include native skill root,
  model argument support, independent provider argument support, read-only audit
  support, final-response capture, and resumable session support.
- Configuration schema :: *Registry-derived harness choices* keep CLI and schema
  aligned; models remain harness-native; providers persist *only where
  meaningful*.
- Runner :: Accept a *typed operation and exact scope*; return *final response*,
  *session identity*, or a *typed incident*.
- Native skill adapters :: *Managed links* under native global skill directories
  point to =~/.agents/skills/<skill>=; the installer owns *only those links*.
- CLI help :: Commands *name supported harnesses*, explain provider
  applicability, and distinguish *workflow installation* from harness or
  credential installation.

**** Immutable audit bundle

Before external audit, the runner creates one *temporary audit bundle* containing
plain, non-symlink copies of the exact specification, project profile, named
authorities, applicable standards, and focused evidence. It *rejects traversal,
symlinks, devices, missing files, duplicates, and oversize input*. A manifest
records source path, destination, byte count, and SHA-256.

The runner makes the *bundle read-only*, includes its contents in the audit
prompt, enables *no tools* where supported, and grants no additional directory.
It verifies *bundle and source hashes* after every call; any change invalidates
the response. Cleanup removes only the exact temporary directory through
program-owned teardown.

**** Initializer mutation boundary

=sdlc-init= requests a typed *project mutation* only after the operator selects
migration or deterministic ledger validation requests one repair. The
initializer first creates the *archived-state branch*, *migration branch*, and
=.sdlc/.init= *recovery record*. The request names one skill, the *project-only
writable root*, expected artefacts, completed stage, and deterministic validator.

An adapter automates the request only with *project-scoped writes* and no
unrestricted filesystem or shell approval. Otherwise the initializer prints an
*exact native skill handoff*, leaves the stage pending, and resumes after
deterministic validation. It *never substitutes a harness*. Failure preserves
the migration branch and recovery record; the archived-state branch remains the
rollback point.

The handoff *prints these labelled fields*: =Harness=, =Executable=, =Project=,
=Skill=, =Scope=, =Expected artefacts=, =Pending stage=, =Recovery record=, and
=Resume command=. The *resume command is exactly =sdlc-init=* from the named
project. It *does not embed an invented provider command*: the operator opens
the *named interactive harness* in that directory, invokes the *named global
skill*, then *reruns the initializer*. RT004.6 asserts every field and confirms
that the *pending stage is unchanged until deterministic validation succeeds*.

*** Alternatives rejected

- Copied provider skills :: Rejected because *four bodies can drift* and
  would require provider-by-provider refresh after every SDLC change.
- Configurable shell command templates :: Rejected because they *collapse
  capabilities*, *widen injection risk*, and make guarantees unauditable.
- Lowest-common-denominator parity :: Rejected because hidden capability gaps
  *weaken gates*; adapters expose exact capabilities and *fail when absent*.
- Project-local provider skills :: Rejected because projects must follow the
  *current global SDLC without reinitialization*.

*** Data and state

- Configuration :: =~/.agents/sdlc.yaml= and =.sdlc/project.yaml= retain *current
  precedence* and phase-specific harness controls.
- Transcripts :: Keep *no runner transcript* outside the native harness store;
  gate evidence records only the *non-secret session identity*.
- Installer state :: Keep *adjacent recoverability backups*; project repositories
  receive *no provider skills*.
- Command-hook state :: Keep one *provider-native registration* that resolves
  the canonical guard; preserve unrelated hook entries and provider settings.
- Managed-link identity requires *exact destination and canonical target*.
  Every regular file or directory is a *conflict requiring one operator
  confirmation*; without confirmation it remains untouched. *No heuristic
  asserts ownership*.
- Confirmed replacement creates an adjacent
  =<basename>.<Unix-seconds>.bak= *before linking*. The *operator-owned backup is
  never auto-deleted*. Recovery restores only the exact path, and RT004.1
  requires *byte, mode, and symlink equivalence*.

*** Failure behaviour

- *Validate executable and capability* before any metered call.
- Return *progress to stderr* and only the *final response and session identity*
  as runner output.
- *Terminate timed-out processes*, record an incident, preserve known identity,
  and *never invent a verdict*.
- *Never fall back* to another harness, provider, or model without explicit
  configured authority.
- *Fail closed on CLI drift* with harness version and expected capability.
- If native hook registration or verification fails, preserve recoverable state,
  name the affected harness and path, and report it as *not SDLC-ready*.

** Architecture impact

*** Security impact

- Threat boundary :: Headless execution adds *provider CLI child processes* and
  named read inputs.
- Data and secrets :: Prompts contain *only specified artefacts and authorities*;
  adapters never dump *environment, credentials, config, or unrelated files*.
- Access :: External auditors receive *read-only bounded input*; initializer
  mutations remain *separately typed and authorized*.
- Command policy :: Every supported harness invokes the *same canonical guard*
  before command execution; no provider-specific adapter may weaken its block
  decisions.
- Conclusion :: *Fixed arguments*, *exact roots*, *no shell evaluation*,
  *capability checks*, and *fail-closed outcomes* are mandatory.

*** Other relevant qualities

- Reliability :: *Fake-executable regressions* isolate protocols; bounded smoke
  tests catch vendor drift without metered CI.
- Performance :: *Native skill links* avoid copies; each gate retains *one
  external context maximum*.
- Operability :: Diagnostics identify *harness, version, phase, exit, and
  identity*; installation remains *plan/apply/verify*.
- Accessibility :: Questions remain *scannable* and do not rely on colour.
- Portability :: Go adapters retain *Darwin/Linux support* and isolate native
  provider paths.
- Maintainability :: *One canonical skill body* and *one typed adapter per
  harness* prevent workflow drift.
