* Specification Summary
:PROPERTIES:
:CUSTOM_ID: summary
:END:

- Outcome :: The *lean SDLC v3 workflow* is *natively usable* from *Codex*,
  *Claude Code*, *GitHub Copilot CLI*, and *Hermes* without duplicating its
  canonical standards or skills.
- Before :: SDLC v3 *installs and runs through Codex only*; installation
  deliberately retires SDLC workflow artefacts from the other three harnesses.
- After :: Each supported harness can *discover the global SDLC skills*, run
  the *same definition and delivery workflows*, and start or resume the *single
  external audit context* through an explicit capability adapter.
- Changes :: Add *Claude*, *Copilot*, and *Hermes* harness adapters; expose the
  *canonical global skills* through each native skill location; make harness
  selection and headless execution *capability-aware*; replace hard-coded
  *Codex* language in the workflow and initializer.
- Unchanged :: The *standards*, *two-gate workflow*, *five-round limit*,
  *operator sign-off*, *Codex support*, and rule against *project-local skill
  copies* remain unchanged.
- Edge cases :: Handle an *absent executable or provider home*, *unsupported or
  meaningless provider option*, *non-SDLC destination conflict*, *unprovable
  read-only mode*, *timeout*, *missing session identity*, and *malformed final
  response* without claiming parity or PASS.
- Decisions :: Keep one *provider-neutral source of truth* under =~/.agents=;
  use *fixed Go adapters*, not shell command templates; treat actual harness
  smoke checks as *bounded one-off tests*, never regression tests.
- Next step :: Definition gate, then operator sign-off.

The summary above accurately and completely represents the detailed
specification below.

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:

** Problem

SDLC v3 was deliberately restored with *one supported harness* so the lean
workflow could be stabilized. The current installer *removes workflow skills*
from Claude, Copilot, and Hermes, the project schema *accepts only Codex*, and
the audit contract *hard-codes Codex*. The same established workflow therefore
cannot be used through the other installed coding agents.

** Outcome

The four harnesses provide the same *SDLC semantics* while their adapters honour
their different native skill paths, command-line arguments, model controls,
provider controls, output formats, and resumable-session mechanisms.

Support means that an operator can invoke the global SDLC skills interactively
and that an SDLC-owned command can run a bounded headless operation when the
workflow requires one. It does not mean that every harness exposes identical
provider, permission, or output features.

** Scope

*** In scope

- Native global-skill exposure for *Claude Code*, *GitHub Copilot CLI*, and
  *Hermes*, while retaining *Codex*.
- Harness selection in global and project YAML configuration.
- Fixed adapters for bounded headless start and resume operations.
- Replacement of hard-coded Codex routing in the initializer and composite
  audit workflow.
- Provider-specific capability checks, least-privilege audit execution,
  installation safety, help text, and public documentation.

*** Out of scope

- Installing a harness, model, authentication credential, subscription, or
  external provider.
- Guaranteeing that all models are offered by every harness.
- Copying SDLC skills into individual software projects.
- Restoring Spec Kit commands or artefacts.
- Supporting an undocumented fifth harness or a generic user-authored command
  template in this change.
- Replacing private provider configuration with public defaults.

*** Unchanged

- =~/.agents/sdlc= remains the canonical deployed standards root.
- =~/.agents/skills= remains the canonical global skill source.
- The authoring context still performs local audits before one retained
  external audit context.
- A timeout, silence, malformed result, or unavailable harness remains a runner
  incident and never becomes an audit PASS.

** Authority and starting point

- Project profile :: [[file:../../.sdlc/project.yaml][=.sdlc/project.yaml=]]
- Product authority :: [[file:../../README.md][=README.md=]] and
  [[file:../../QUICKSTART.md][=QUICKSTART.md=]] define installation and operator
  use.
- Architecture authority :: [[file:../../docs/ARCHITECTURE.md][=docs/ARCHITECTURE.md=]]
  defines the canonical runtime tree, provider boundary, and two-context gates.
- Historical evidence :: Tag =v2.0.0= shows that the installer previously
  deployed skills to Claude, Copilot, and Hermes, but copied them rather than
  preserving one canonical global source.
- Current implementation fact ::
  [[file:../../internal/installer/installer.go][=internal/installer/installer.go=]]
  currently retires SDLC skills from non-Codex homes, and
  [[file:../../src/config/project-init.schema.yaml][=src/config/project-init.schema.yaml=]]
  permits only Codex and OpenAI choices.
- Observed harness interfaces :: The current command contracts are recorded in
  the [[#harness-capability-contract][harness capability contract]]. They must be
  revalidated during implementation rather than treated as permanent vendor
  guarantees.
- External contract :: None.

** Constraints and dependencies

- Provider adapters must be *thin*. Shared workflow rules and skill bodies must
  not fork by harness.
- Executable names and arguments must be selected from compiled, allowlisted
  adapter code. Configuration must never supply an executable or shell command
  template.
- Persistent regression tests must use temporary homes and fake harness
  executables. They must not invoke a metered model or modify real provider
  configuration.
- Provider-native paths may contain unrelated personal material. Installation
  must preserve it and must not mistake a same-named non-SDLC artefact for
  disposable output.

** Decisions

- Native skill locations expose each SDLC skill through a managed link to its
  canonical =~/.agents/skills/<skill>= directory. They do not contain copied
  skill bodies.
- A shared Go harness registry supplies supported names and capabilities to the
  initializer, installer, and runner. Each adapter constructs its own fixed
  argument vector.
- =provider= is passed only by an adapter whose harness supports an independent
  provider option. It is ignored for invocation when the harness selects its
  provider internally; an incompatible explicit project override is reported
  rather than silently translated.
- External audit adapters must obtain a stable session identity on the first
  call and resume that exact context after remediation. If this cannot be
  established, the gate stops.

** Unresolved blockers

- None.

* Edge Cases
:PROPERTIES:
:CUSTOM_ID: edge-cases
:END:

** Provider home is absent

- Condition :: A supported harness executable exists but its native skill home
  has not been initialized.
- Required behaviour :: Installation creates only the documented skill path or
  stops with the exact prerequisite; it does not invent provider configuration.
- Covered by :: [[#ac-004-6][AC004.6 - Safe and idempotent installation]] and
  [[#rt-004-1][RT004.1 - Install native global skill adapters]].

** Native skill name conflicts

- Condition :: A provider home already contains a same-named path that is not a
  recognized SDLC-managed adapter.
- Required behaviour :: The installer reports the exact conflict and requires
  operator disposition; it does not overwrite, merge, or retire the path.
- Covered by :: [[#ac-004-6][AC004.6 - Safe and idempotent installation]] and
  [[#rt-004-1][RT004.1 - Install native global skill adapters]].

** Harness cannot prove read-only execution

- Condition :: A harness version lacks the adapter capability needed to prevent
  external-auditor mutation.
- Required behaviour :: External audit stops as unsupported for that harness;
  definition or delivery does not weaken the audit boundary or silently switch
  harnesses.
- Covered by :: [[#ac-004-5][AC004.5 - Read-only audit boundary]] and
  [[#rt-004-4][RT004.4 - Reject invalid audit runner outcomes]].

** Provider is meaningless to the selected harness

- Condition :: Configuration inherits a provider value while Claude, Copilot,
  or Codex owns provider selection internally.
- Required behaviour :: The adapter does not pass the value. An inherited
  irrelevant value may be ignored with concise evidence; an explicit conflicting
  project override is reported for correction.
- Covered by :: [[#ac-004-3][AC004.3 - Capability-aware phase configuration]]
  and [[#rt-004-2][RT004.2 - Resolve harness configuration]].

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Relevant components :: The installer, initializer, YAML configuration schema,
  global skills, composite audit rules, and a new internal harness runner.
- Ownership boundary :: This repository owns SDLC adapters and invocation
  semantics. Each harness owns authentication, available models, native session
  storage, and CLI compatibility.
- Existing pattern :: Retain the installer plan/apply/verify pattern and the
  schema-driven initializer. Replace the v3 non-Codex retirement branch rather
  than layering installation after it.

** High-level design

*** Flow

1. A *compiled registry* declares four supported harnesses and their stable
   configuration and routing capabilities.
2. =sdlc-install= exposes *canonical skills* through each native global skill
   path while preserving provider-owned material.
3. Interactive harnesses invoke the *same skill bodies*, selected standards,
   and project authorities.
4. A bounded headless operation uses one *fixed adapter* with exact scope,
   model, applicable provider, timeout, and output contract.
5. An external composite audit records one *stable session identity* and uses
   the *same adapter and identity* for every permitted resume.

The runner is used only after all required *same-context local audits pass*.
It never replaces local review and never starts one external context per focused
audit.

*** Interfaces and configuration

**** Harness capability contract
:PROPERTIES:
:CUSTOM_ID: harness-capability-contract
:END:

The following table is the current implementation target. =PROMPT= is supplied
as data, never evaluated by a shell. =BUNDLE= is an isolated temporary audit
directory. Implementation first rechecks each installed command's help and
fails visibly if its contract has drifted.

| Harness | Native global skill path | Audit start | Stable identity | Audit resume | Model | Provider | Final response |
|---------+--------------------------+-------------+-----------------+--------------+-------+----------+----------------|
| Codex | =~/.agents/skills= | =codex exec -m MODEL -s read-only -C BUNDLE --json -o RESULT -= | =thread.started.thread_id= from JSONL | =codex exec resume -m MODEL --json -o RESULT SESSION -= from =BUNDLE= | =-m= | none | non-empty =RESULT= |
| Claude | =~/.claude/skills= | preassigned UUID with =claude -p --output-format json --model MODEL --session-id UUID --tools "" --permission-mode plan PROMPT= | preassigned UUID | replace =--session-id UUID= with =--resume UUID= | =--model= | none | JSON =result= |
| Copilot | =~/.copilot/skills= | unique name with =copilot -p PROMPT -s --output-format json --model MODEL --name NAME --available-tools== | preassigned name | replace =--name NAME= with =--resume=NAME= | =--model= | none | final assistant event from JSONL |
| Hermes | =~/.hermes/skills= | =hermes -z PROMPT -m MODEL --provider PROVIDER -t "" --pass-session-id --safe-mode --in BUNDLE= | validated =SESSION_ID= field in the response | replace =--pass-session-id= with =--resume SESSION= | =-m= | =--provider= | non-empty stdout minus the identity envelope |

For Claude, Copilot, and Hermes, the empty tool selection must be proven to
expose *no tools*. If a current version cannot do that, its adapter may still
provide interactive skills but must report external audit as unavailable.
Codex runs against the audit bundle with its documented read-only sandbox.

- Response envelope :: The runner requires a non-empty final response and one
  valid stable identity. Hermes additionally returns
  =SESSION_ID: <native-id>= before the composite gate verdict. Missing,
  duplicated, or malformed fields are runner incidents.
- Incident kinds :: =executable-unavailable=, =capability-unsupported=,
  =configuration-invalid=, =start-failed=, =identity-missing=,
  =response-empty=, =response-malformed=, =timeout=, =resume-failed=, and
  =audit-input-mutated=.
- Process control :: Start each command directly from a Go argument slice,
  stream progress through the runner's stderr channel, capture only structured
  protocol output, and on timeout terminate the process group before returning
  partial output as diagnostic evidence rather than a verdict.

- Harness registry :: A Go interface and fixed registrations for =codex=,
  =claude=, =copilot=, and =hermes=. Capabilities include native skill root,
  model argument support, independent provider argument support, read-only audit
  support, final-response capture, and resumable session support.
- Configuration schema :: Harness choices come from the supported registry or a
  generated schema input so the CLI and schema cannot disagree. Model values
  remain harness-native strings. Provider values are requested and persisted
  only where they have invocation meaning.
- Runner :: Accepts a typed operation, project root, exact additional readable
  roots, prompt, harness, model, optional provider, timeout, and optional session
  identity. It returns final response text, session identity, and typed incident.
- Native skill adapters :: Managed links under each provider's documented global
  skill directory point to =~/.agents/skills/<skill>=. The installer owns only
  those exact links.
- CLI help :: =sdlc-install= and =sdlc-init= name supported harnesses, explain
  provider applicability, and distinguish workflow installation from harness
  or credential installation.

**** Immutable audit bundle

Before external audit, the runner creates one *temporary audit bundle* containing
plain, non-symlink copies of the exact specification, project profile, named
authorities, applicable standards, and focused evidence. It *rejects traversal,
symlinks, devices, missing files, duplicates, and oversize input*. A manifest
records source path, destination, byte count, and SHA-256.

The runner makes the *bundle read-only*, includes its contents in the audit
prompt, enables *no tools* where supported, and grants no additional directory.
It verifies *bundle and source hashes* after every call; any change invalidates
the response. Cleanup removes only the exact temporary directory through
program-owned teardown.

**** Initializer mutation boundary

=sdlc-init= requests a typed *project mutation* only after the operator selects
migration or deterministic ledger validation requests one repair. The
initializer first creates the *archived-state branch*, *migration branch*, and
=.sdlc/.init= *recovery record*. The request names one skill, the *project-only
writable root*, expected artefacts, completed stage, and deterministic validator.

An adapter automates the request only with *project-scoped writes* and no
unrestricted filesystem or shell approval. Otherwise the initializer prints an
*exact native skill handoff*, leaves the stage pending, and resumes after
deterministic validation. It *never substitutes a harness*. Failure preserves
the migration branch and recovery record; the archived-state branch remains the
rollback point.

*** Alternatives rejected

- Copied provider skills :: Rejected because four deployed bodies can drift and
  would require provider-by-provider refresh after every SDLC change.
- Configurable shell command templates :: Rejected because they collapse unlike
  capabilities into strings, widen command-injection risk, and make permission
  and resume guarantees unauditable.
- Lowest-common-denominator parity :: Rejected because hiding unsupported
  provider or read-only controls would weaken the established gates. Adapters
  expose exact capabilities and fail when a required capability is absent.
- Project-local provider skills :: Rejected because projects must follow the
  current global SDLC without reinitialization.

*** Data and state

- =~/.agents/sdlc.yaml= and =.sdlc/project.yaml= retain the current precedence
  and phase-specific =harness=, =provider=, =model=, and audit =timeout= fields.
- The runner keeps no transcript outside the native harness store. Gate evidence
  records the non-secret session identity needed to resume.
- Installer backups remain adjacent recoverability artefacts under the existing
  managed-install contract; project repositories receive no provider skills.
- Recognized v1/v2 SDLC-owned provider copies are backed up and replaced by
  canonical links. A same-named path not proven SDLC-owned is a conflict.

*** Failure behaviour

- Validate executable presence and adapter capability before any metered call.
- Return stderr progress to the operator while capturing only the final response
  and machine-readable session identity as runner output.
- Kill a timed-out child process, record a runner incident, and preserve a known
  session identity without inventing a verdict.
- Never fall back to another harness, provider, or model unless a separately
  documented operator configuration explicitly requests that behaviour.
- If vendor CLI drift breaks parsing or scope controls, fail closed with the
  harness version and expected capability.

** Architecture impact

*** Security impact

- Threat boundary :: Headless harness execution adds provider CLIs as controlled
  child processes and exposes named project and standards paths for reading.
- Data and secrets :: Prompts contain only the specified artefact and named
  authorities. Adapters must not dump environment variables, provider config,
  credentials, unrelated home content, or hidden files into prompts or logs.
- Access :: External auditors receive read-only access to the project, canonical
  SDLC, and explicit additional authority roots. Mutation-capable initializer
  operations remain separately typed and only run where the governing workflow
  authorizes writes.
- Conclusion :: Fixed argument vectors, exact roots, no shell evaluation,
  capability checks, and fail-closed outcomes are mandatory. A harness without
  enforceable audit immutability is not an external-audit adapter.

*** Other relevant qualities

- Reliability :: Fake-executable regression tests isolate CLI construction and
  parsing; bounded real smoke tests catch vendor drift without creating metered
  CI.
- Performance :: Native skill links avoid repeated copies and context loading is
  unchanged. One external context remains the maximum per gate.
- Operability :: Diagnostics identify harness, version, phase, exit state, and
  retained session identity. Installation remains plan/apply/verify.
- Accessibility :: Installer questions and diagnostics retain the established
  scannable layout and do not encode meaning through colour alone.
- Portability :: Go adapters support the repository's Darwin/Linux target;
  provider path differences are isolated in the registry.
- Maintainability :: One canonical skill body and one typed adapter per harness
  prevent four drifting workflow implementations.
