* Prototype an isolated Claude auditor

- Outcome :: Qualify an *independent auditor* with *bounded context* in paired iterations.
- Before :: Existing audits can spend substantial effort loading unrelated instructions.
- After :: An *opt-in prototype* invokes *Claude safe mode*, with no delivery tools.
- Changes :: First slice tests startup, structured results, timeout and retained-session resume.
- Unchanged :: Normal harnesses, personal configuration, installed SDLC and canonical audit records.
- Edge cases :: Authentication failure, timeout, malformed output and session mismatch fail explicitly.
- Decisions :: Start with *Sonnet* and *all operational tools disabled*. Claude's structured-response tool remains permitted. Synthetic evidence is inline for this first probe only.
- Next step :: Review the bounded native Read-permission result before integrating original-file evidence into the prototype.

* Acceptance Criteria

** AC007.1 - Explicitly isolated invocation
:PROPERTIES:
:CUSTOM_ID: ac-007-1
:END:

- Criterion :: The prototype starts *Claude safe mode* with an explicit audit prompt and *no operational tools*, without changing ordinary user configuration. Claude's internal structured-response tool is permitted solely to return the result.
- Proven by :: [[#ot-007-1][OT007.1 - Live isolation probe]].

** AC007.2 - Bounded, structured response
:PROPERTIES:
:CUSTOM_ID: ac-007-2
:END:

- Criterion :: A successful invocation returns a native session identity and a *validated structured response*. Timeout, provider error, empty or malformed output produces *no accepted verdict*.
- Proven by :: [[#rt-007-1][RT007.1 - Local response validation]], [[#ot-007-1][OT007.1 - Live isolation probe]].

** AC007.3 - Same-session continuation
:PROPERTIES:
:CUSTOM_ID: ac-007-3
:END:

- Criterion :: Explicit resume uses the *returned native identity* and rejects a different returned session. Runtime state remains in the caller-selected scratch configuration directory until the paired probe is reviewed.
- Proven by :: [[#rt-007-1][RT007.1 - Local response validation]], [[#ot-007-2][OT007.2 - Live retained-context probe]].

* Test Definitions

** RT007.1 - Local response validation
:PROPERTIES:
:CUSTOM_ID: rt-007-1
:END:

- Covers :: [[#ac-007-2][AC007.2 - Structured response]], [[#ac-007-3][AC007.3 - Same-session continuation]].
- Procedure :: Feed documented synthetic Claude result envelopes to the parser; reject provider errors, missing fields, invalid verdicts and mismatched sessions.
- Boundary :: Local parser only; *no model invocation* in regression tests.

** OT007.1 - Live isolation probe
:PROPERTIES:
:CUSTOM_ID: ot-007-1
:END:

- Covers :: [[#ac-007-1][AC007.1 - Isolated invocation]], [[#ac-007-2][AC007.2 - Structured response]].
- Procedure :: One Sonnet invocation with a tiny synthetic requirement and deliberately defective implementation. Supply synthetic CLAUDE.md instruction markers in the scratch configuration and working directory. Inspect native output and transcript for tool availability and marker contamination.
- Expected :: The defect is identified, structured output is valid, and the synthetic instruction markers are absent from the response. Absence alone is not proof of every instruction-loading path.
- Bounds :: One call, at most two minutes; no retries, real project data, external writes requested of the model or metered regression target. Subscription usage is not assumed free or sufficient.
- Record :: [[file:validation.org][Paired validation record]].

** OT007.2 - Live retained-context probe
:PROPERTIES:
:CUSTOM_ID: ot-007-2
:END:

- Covers :: [[#ac-007-3][AC007.3 - Same-session continuation]].
- Procedure :: One resume of the returned identity with corrected synthetic implementation, without repeating the original requirement.
- Expected :: Same session, correction evaluated against retained requirement.
- Bounds :: One call, at most two minutes; no automatic retry. Follow only after the startup probe yields a native identity.

** OT007.3 - Native file-permission qualification
:PROPERTIES:
:CUSTOM_ID: ot-007-3
:END:

- Purpose :: Qualify the proposed original-path evidence boundary before adding file access to the prototype.
- Procedure :: In a separate synthetic scratch workspace, expose only Claude's =Read= and structured-response tools. Permit one exact original file and one symlink spelling; the symlink points to an unlisted sibling. Request all three reads explicitly. Deny the scratch working directory and authentication directory. Inspect native tool results, not merely the final model report.
- Expected :: The permitted file is readable; the unlisted sibling and symlink target are refused by deterministic permissions. A successful unlisted read rejects this configuration as an evidence allowlist.
- Bounds :: One subscription-backed Sonnet invocation, two-minute external process timeout with a two-second kill escalation, and =--max-turns 4=; no retry, real project files or metered regression test. Runtime configuration remains isolated. Retain synthetic results in operating-system scratch space for paired inspection.
- Scope :: A one-off capability experiment, not a production change or an implementation claim for a new acceptance criterion.

* Edge Cases

- *No authentication* :: Report it without extracting credentials or switching billing providers.
- *No session after timeout* :: Report the incident; do not invent a resumable identity.
- *Invalid output* :: Reject it, preserving diagnostic evidence for paired review.

* Solution Design

- Location :: Standalone =prototype/claude-audit/=; not installed or used by the production runner.
- Contract :: Prompt and response schema are reviewable files, not embedded prose. The wrapper accepts a scratch configuration directory and optional native resume ID. One invocation per command; stdout is YAML and stderr is diagnostic output.
- Security :: The model receives *no shell, file, network or delegation tools*. Safe mode intentionally suppresses ordinary hooks, so this slice does not rely on them for enforcement. Managed policies remain authoritative. No permission bypass flags.
- Runtime :: Claude owns authentication; logs and retained sessions are redirected to scratch. No credentials are printed or copied. Structured JSON transport is parsed and serialized to YAML by the wrapper.
- Limits :: This is *not yet a file-access sandbox* or a canonical gate. Its stdout is experimental evidence, not an update to =audits.yaml=.

The next paired slice tests Claude's native =Read= permissions using original
synthetic paths, =dontAsk=, explicit file grants and an empty, read-denied working

harness. Safe mode remains enabled and no other operational tools are exposed.
The newer =blockReadsOutsideWorkingDirectories= option is not used: its documented
minimum is later than the tested Claude Code 2.1.236.
