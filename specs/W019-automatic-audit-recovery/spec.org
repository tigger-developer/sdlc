* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:
** Outcome
- Calling agents request *audits*, without managing provider sessions or failures.
** Before
- Every provider attempt consumed the audit allowance; malformed output was unavailable for investigation.
** After
- *Valid verdicts alone* consume a ticket-and-gate allowance.
- The harness *clarifies malformed output*, logs diagnostics and stops within an internal bound.
** Changes
- Use *one normal invocation* and operator-authorized =--reset=.
- Default internal failure limit to *three*, configurable separately from verdicts.
** Unchanged
- Preserve *findings, history, evidence integrity, readiness and operator authority*.
- Installation remains *operator-run*; other projects and provider configuration are unchanged.
** Edge cases
- Authentication failure *immediately tries fallback*; failure there stops for intervention.
- Internal lockout *survives subsequent invocations* until authorized reset.
** Decisions
- Retain *private project-local logs* and gate-specific reset boundaries.
** Next step
- Review verification evidence, install through the existing release path and validate operation.

* Acceptance Criteria
** AC019.1 - Automatic invocation :ac:
:PROPERTIES:
:CUSTOM_ID: ac019-1
:END:
- Criterion :: A caller supplies project, work item, gate, audit record and evidence;
  the harness *selects or creates its context*. Public =--session= is rejected and
  session identifiers are not exposed in normal diagnostics.
- Proven by :: [[#rt019-1][RT019.1 - Automatic recovery]] and [[#ot019-1][OT019.1 - Documentation and packaging]].

** AC019.2 - Independent verdict and failure limits :ac:
:PROPERTIES:
:CUSTOM_ID: ac019-2
:END:
- Criterion :: *Only valid PASS, PROVISIONAL PASS and FAIL* consume the selected
  ticket-and-gate allowance, default five. Cached results consume none.
  An unusable response consumes only the internal consecutive-failure allowance,
  default three. A valid response clears its failure streak. Reaching the internal
  bound *locks that gate until reset*, without disclosing an internal count.
- Proven by :: [[#rt019-1][RT019.1 - Automatic recovery]], [[#rt019-2][RT019.2 - Gate budgets and configuration]].

** AC019.3 - Bounded remediation and authentication fallback :ac:
:PROPERTIES:
:CUSTOM_ID: ac019-3
:END:
- Criterion :: A malformed response receives a *format clarification in the retained
  context* when available. Recovery remains bounded across primary and fallback.
  Authentication failure *tries the configured fallback immediately*; failure there,
  or no configured fallback, causes immediate intervention rather than repeated login attempts.
- Proven by :: [[#rt019-1][RT019.1 - Automatic recovery]] and [[#ut019-1][UT019.1 - Installed use]].

** AC019.4 - Authorized reset :ac:
:PROPERTIES:
:CUSTOM_ID: ac019-4
:END:
- Criterion :: Authorized =--reset= *clears both selected-gate counters*, retires its
  provider context and exits without a model call. The next audit uses fresh context
  and does not reuse pre-reset cached verdicts. *History, logs and other gates' counts
  remain intact*. Repeating reset before another audit changes nothing.
- Proven by :: [[#rt019-1][RT019.1 - Automatic recovery]], [[#rt019-2][RT019.2 - Gate budgets and configuration]].

** AC019.5 - Investigable failure without agent troubleshooting :ac:
:PROPERTIES:
:CUSTOM_ID: ac019-5
:END:
- Criterion :: Received output and provider errors remain in *bounded private logs*,
  distinct from validated verdicts. An internal failure returns *human intervention
  required* and a diagnostic reference, not provider repair instructions or retry counts.
- Proven by :: [[#rt019-1][RT019.1 - Automatic recovery]], [[#ot019-1][OT019.1 - Documentation and packaging]], [[#ut019-1][UT019.1 - Installed use]].

* Edge Cases
- Legacy unlabelled implementation rounds remain *historical evidence*, not invented
  test-code/delivery-code verdicts. Existing reset boundaries remain meaningful.
- Cached results never erase a lockout. Raised configuration limits do not clear
  a recorded internal stop. Only authorized reset clears it.
- Missing identity permits a bounded fresh context, not an invented native ID.
- Readiness, configuration, evidence mutation and record-write failures stop locally;
  recovery does not suppress them or widen provider permissions.

* Solution Design
** Responsibilities and state
- =main.go= coordinates invocation and selects the recorded context automatically.
- =recovery.go= owns bounded retry, format clarification, authentication fallback and
  cooldown routing; native adapters remain unchanged except diagnostic capture.
- =audit_record.go= derives gate-specific counts from retained history and reset
  boundaries. =external_round= remains *lifetime attempt provenance*, not the verdict budget.
- =diagnostics.go= owns *private capped logs*; unvalidated output never becomes a verdict.

** Interface and configuration
#+begin_src sh
sdlc-harness --gate delivery-code --project . \
  --audit-record specs/WNNN-change/audits.yaml --work-item WNNN --input source.go
sdlc-harness --reset --gate delivery-code --project . \
  --audit-record specs/WNNN-change/audits.yaml --work-item WNNN
#+end_src
- Default verdict allowance :: =delivery.audit.max_rounds: 5=.
- Internal failure bound :: =delivery.audit.max_failures: 3=, positive integer;
  project YAML overrides global YAML.
- Compatibility :: Legacy =start= and =resume= operation words select automatic audit
  behaviour during transition; omit them in new instructions. =--session= and
  =--reset-session= are removed. No existing audit history is deleted.
- Reset scope :: The selected ticket/gate's counters reset; its shared provider
  context is retired. Other gates retain their budget history.

** Security and design verification
- Logs :: =.sdlc/audit-diagnostics/= contains 0600 files in a created 0700 directory,
  with its own ignore rule. Each invocation retains at most 16 MiB. Logs may contain
  reviewed material and remain operator-controlled; no upload or deliberate prompt copies.
- Recovery :: All calls retain configured deadlines and read-only adapter controls.
  Tests use temporary local fixtures; live provider state is not part of regression.
- Structural check :: One recovery coordinator and one gate-counter implementation;
  no new provider framework, global state, billing logic or credential management.
